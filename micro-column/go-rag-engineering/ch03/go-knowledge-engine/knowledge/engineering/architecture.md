# 系统架构与服务边界

## 1. 系统概览

当前系统采用面向业务能力拆分的服务架构。

用户服务负责处理用户侧业务请求，订单服务负责订单创建、查询和状态管理。

服务之间通过 HTTP 接口进行通信。

## 2. 核心服务

### 用户服务

用户服务负责：

- 接收和处理用户请求。
- 管理用户相关业务流程。
- 调用订单服务完成订单操作。

### 订单服务

订单服务负责：

- 创建订单。
- 查询订单信息。
- 更新订单状态。
- 管理订单业务数据。

## 3. 服务调用关系

用户服务依赖订单服务提供的 HTTP 接口。

```text
用户请求
   |
   v
用户服务
   |
   | HTTP
   v
订单服务
   |
   v
订单数据
```

用户服务调用订单服务时，需要明确设置请求超时时间，并对下游异常进行处理。

## 4. 设计约束

服务之间应保持清晰的职责边界。

调用方不能假设下游服务始终可用，需要考虑：
- 请求超时。
- 网络异常。
- 重试策略。
- 熔断保护。
- 连接池资源限制。
