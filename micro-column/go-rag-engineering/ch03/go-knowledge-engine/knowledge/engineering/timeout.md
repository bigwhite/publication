# 服务调用超时与重试规范

## 1. 为什么需要超时控制？

用户服务调用订单服务时，不能无限期等待下游响应。

如果没有明确的请求超时时间，下游服务发生故障时，调用方可能长期占用 Goroutine、连接和其他资源。

大量请求堆积还可能进一步放大故障。

因此，服务间调用必须设置明确的超时策略。

## 2. HTTP 请求超时

单次 HTTP 请求超时时间建议为 2 秒。

调用方应根据业务特点设置合理的超时时间，避免请求长期阻塞。

## 3. 调用链路总超时

单次请求超时并不等于整个业务调用链路的超时。

整个业务调用链路的总超时时间不得超过 5 秒。

调用方应确保各次下游调用和重试所消耗的时间都受到总超时预算约束。

## 4. 重试策略

默认最多重试 2 次。

重试必须设置最大次数，不能无限重试。

对于非幂等请求，不得在没有幂等保护的情况下自动重试。

## 5. 熔断机制

当下游服务持续超时或出现异常时，应结合熔断机制限制请求量。

熔断可以避免大量失败请求持续冲击下游服务。

## 6. 常见风险

### 没有请求超时

请求可能长期占用资源，造成调用方资源耗尽。

### 无限重试

下游服务响应变慢时，重试可能进一步增加请求量。

### 非幂等请求自动重试

可能导致重复创建订单或重复执行业务操作。

### 没有熔断保护

下游持续异常时，调用方仍然可能不断发送请求。
