# 部署与监控规范

## 1. 部署原则

服务部署需要保证配置明确、过程可追踪，并具备基本的健康检查能力。

部署过程应关注：

- 服务启动状态。
- 配置是否正确加载。
- 下游依赖是否可用。
- 日志是否正常输出。

## 2. 运行监控

对于用户服务和订单服务，需要持续关注以下指标：

- HTTP 请求延迟。
- HTTP 请求错误率。
- 下游服务超时次数。
- 重试请求数量。
- 连接池使用率。
- 服务健康状态。

## 3. 超时与连接池监控

如果订单服务出现响应变慢，需要结合请求延迟和连接池使用率进行排查。

尤其需要关注重试请求是否导致下游请求量异常增长。

## 4. 故障排查

当用户服务调用订单服务出现超时，可以按照以下顺序排查：

1. 检查订单服务健康状态。
2. 查看 HTTP 请求延迟和超时数量。
3. 检查用户服务的重试次数。
4. 查看订单服务连接池使用率。
5. 检查是否触发熔断机制。
